# 设计原则 — 为什么这个 harness 长这样

## 定位

ai4omics 不是"让 LLM 自由发挥调工具"的 agent 框架，而是**确定性流水线 + 监督门控 + 可选 LLM 判读**：

- 重计算（DEG/ChIP/富集）全部是版本化脚本，不消耗 token、结果可复现；
- LLM 只放在语义层（新颖性判读、异常归因、假设质询），不配置就退化为规则模式；
- 与 Biomni/GenoMAS 的区别：那类系统优化"从自然语言出分析"，本框架优化"同一筛选每月重跑、结果可审计、可写进论文方法学"。

## 四个核心机制

### 1. 三方哈希状态（state.json）

每个阶段记录 `脚本哈希 + 输入产物哈希 + 输出产物哈希 + QC 结论 + 失败类别`。
重跑时先对哈希：脚本改了→重跑；输入变了→重跑；都没变→跳过。
解决的问题：脚本悄悄改了但结果没更新；中途失败留下半成品被当成品。

### 2. 失败分类恢复（errors.py）

| 类别 | 例 | 恢复 |
|---|---|---|
| transient | 网络抖动、HTTP 429/5xx、SSL | 指数退避 2→8→20s，重试 3 次 |
| schema | 缺文件、缺列、编码错 | 重试 1 次，仍失败换解析/换数据源 |
| logic | QC 不达标、断言失败 | 不重试，记录并中止（重试只会扩大错误） |
| budget | 子进程超时 | 不重试，调阈值 |

"所有失败都重试 3 次"是最常见的 harness 反模式——它把逻辑错误放大三倍。

### 3. 产物契约（contract）

pipeline.yaml 里声明产物的**必需列**，缺列即失败。
行数区间能拦住"文件在但内容空"，拦不住"列改名导致下游 KeyError"——契约拦得住。

### 4. 负对照（negative control）

每个筛选结论配一个"随机能得几分"的基线：
- **置换检验**：打乱一层标签 5000 次，看观察命中数落在零分布哪里；
- **经验 p 值**：候选的模式（如"5 体系一致上调"）在全部背景基因里出现频率多少。

负对照可能给出"不显著"的结论——这是特性不是缺陷（见 examples/yap1_breast 的实际结果）。

## 已知边界（诚实清单）

- critic 阶段（逐条质询证据同源性）在路线图上，未实现；
- 阈值（如 DEG 1000–3000 校准网格）是领域约定，不是统计最优；
- 负对照的置换检验假设标签可交换，IP-MS 丰度偏倚会削弱该假设；
- hg19/hg38 混用的坐标一致性检查未内置，跨组学项目务必自查。
